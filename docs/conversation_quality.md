# Conversation Quality

## 目的

Version 1.3では、PersonalAIの会話品質方針を追加した。

会話品質は、LLMの出力を完全に固定するものではない。
ユーザー入力の種類に応じて、返答の長さ、温度感、説明の整理方法を軽く方向づける。

## 共通方針

- ユーザーの入力に直接答える
- 分からないことは断定しない
- 実行していないことを実行したと言わない
- 未実装機能は未実装と正直に言う
- MemoryやPreferenceを必要以上に出さない
- 内部機能名や実装名を必要以上に出さない

## 通常会話

通常会話では、短めで自然に返す。

例:

```text
こんにちは
ありがとう
疲れました
応援してください
雑談しよう
```

方針:

- 短めで自然に返す
- 返答は1〜3文を目安にする
- ユーザーが求めていない情報を広げすぎない
- MemoryやPreferenceを無理に出さない
- 好きな食べ物などの過去情報を、関係ない雑談に混ぜない

## 相談

相談では、まず結論を出し、理由や選択肢を短く整理する。

例:

```text
どうしたらいいですか
おすすめはありますか
どちらがいいですか
リスクはありますか
提案はありますか
```

方針:

- まず結論を出す
- 理由を短く説明する
- 必要なら現実的な選択肢を最大3つまで出す
- リスクがある場合は明確に伝える
- 押しつけず、ユーザーが選びやすい形にする

## 開発補助

開発補助では、手順、変更対象、確認コマンド、注意点を整理する。

例:

```text
Pythonでエラーが出ました
app.pyを確認してください
Git commit前に何をすればいいですか
scriptsのcheckを整理したい
```

方針:

- 手順を順番に整理する
- 手順は最大4項目を目安にし、長くなりすぎない
- 変更対象を明確にする
- 確認コマンドを明確にする
- 注意点を先に伝える
- 危険な操作は先に止める
- 初心者にも分かるように書く
- 好きな食べ物などのPreference情報は、開発相談では出さない

## 不明・未実装

不明なことや未実装機能では、できるふりをしない。

方針:

- 分からないことは分からないと言う
- 不明点を断定しない
- 実行していないことを実行したと言わない
- Web、PDF、YouTube、画像などの未実装読み取りは未実装と正直に言う
- 必要なら代替案を短く提案する

## データ分析・集計の正直さ（Ver2.40時点、方針のみ・未実装）

Excel Reader（Ver2.37〜2.38）の実機テストで、以下の課題が見つかった。

- 事前計算済みの正しい集計値（合計・平均など）が資料内にあるにもかかわらず、質問に対して受け流すだけで値を使わない場合がある
- グループ集計（例:「一番売れた商品は？」のような、列をまたぐ集計・比較）はまだ実装していないにもかかわらず、Qwenが自己流に計算し、検証されていない値を断定的に答えてしまう場合がある

これはExcel Reader固有の実装不足というより、Qwen（qwen3:8b）の推論能力・応答の一貫性に起因する部分が大きいと判断し、Ver2.40時点では修正しない。

ユーザーからは、将来的に以下を実現してほしいという方針を確認した。

- 分からない・自信がない場合は、断定せず正直に「分からない」「未対応」と言えるようにする（今回のような未実装のグループ集計に対して、検証されていない値を断定的に答えないようにする）
- Qwen（ローカルモデル）自体の性能・推論能力を向上させる方法を検討する
- Qwenで精度が不十分な場合に、必要に応じてOpenAIを頼れるようにする（`MIGRATION.md`の「Qwen / OpenAIの利用方針」で整理した月間上限額制の仕組みを実装する）

これらは会話品質・ModelRouter・OpenAI接続に関わる本格的な設計判断であり、個別のReader実装ではなく、PersonalAI本体の応答品質・モデル選択の仕組みとして扱う。
着手する場合は、あらためてユーザーと設計を確認する。

## 実装メモ

会話品質の軽い分類は `ai/conversation_quality_policy.py` で行う。

主な分類:

- `casual`: 通常会話
- `advice`: 相談
- `development`: 開発補助
- `unknown`: その他

`build_conversation_quality_guidance()` が、ユーザー入力と `memory_usage` に応じたガイダンス文を作る。
PersonalAI本体は、このガイダンスをsystem messageとしてLLMに渡す。
