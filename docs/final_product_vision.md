# Final Product Vision

## 目的

このドキュメントは、PersonalAIの完成形ビジョンを整理するための設計メモである。

Ver2.7では、完成形に向けた高自律、記憶、ModelRouter / ToolRouter、自己アップデート、自律調査、UI方針をdocs化する。
今回は実装ではなく、今後の判断基準を失わないための整理である。

## 1. 最上位方針

PersonalAIの完成形は、以下を重視する。

- 精度最優先
- 基本的に何でもできる万能AIを目指す
- 想定外の操作でも壊れにくい安全性
- 優秀な人間が隣にいるような快適さ
- ユーザーの好みに合わせて様々なことを調整できる
- 危険操作・機密情報・金銭操作の暴走防止
- 現実世界に大きな影響を与える暴走を防ぐ
- なるべく維持費を抑える

PersonalAIは、単に会話するAIではなく、ユーザーの目的を理解し、必要な道具を選び、実行し、確認し、必要ならやり直す統括システムを目指す。

## 2. 高自律が基本

PersonalAIは、基本は高自律で動ける設計を目指す。

ただし、自律性は固定ではなく、ユーザーが必要に応じて下げられることが重要である。

基本方針:

- 基本は高自律
- ユーザーが必要に応じて自律レベルを下げられる
- 危険操作・機密情報・金銭・外部送信・削除・公開・Permission緩和は別枠で強く制御する
- 高自律でも、重要な確認を飛ばしてよいわけではない

高自律とは、勝手に危険操作をすることではない。
ユーザーの目的に沿って、低リスクな判断や後から直せる細部をAI側で進め、重要な分岐だけ確認することである。

## 3. 確認レベル

確認レベルは「commit前だけ確認」のような開発専用設定ではなく、より一般的な自律レベルとして扱う。

想定する自律レベル:

- 手動
- 共同作業
- 半自動
- 自動実行寄り
- 高自律

開発作業では、この自律レベルの上に作業別ルールを重ねる。

開発作業の例:

- docs更新は自動可
- check追加は自動可
- テスト実行は自動可
- ファイル編集は設定次第
- commitは確認
- pushは確認
- tag / Releaseは必ず確認
- DB変更は必ず確認

ユーザーは、会話で次のように指定できる状態を目指す。

```text
Ver2.xの間は、危険操作・大きな問題・重要な質問・重要な提案がない限り半自動で進めて
```

## 4. 会話で調整できる設定

PersonalAIは、会話の中で以下を調整できるようにする。

- 確認頻度
- 自律レベル
- 提案量
- 質問量
- 雑談量
- 説明量
- 通知頻度
- モデル使用方針
- 低コスト優先 / 高性能優先

固定プリセットも用意できるようにする。

プリセット例:

- 慎重モード
- 標準モード
- 半自動モード
- 集中開発モード
- 高自律モード
- 高性能モデル優先モード
- 低コストモード
- 雑談少なめモード
- 初心者向け説明モード

設定は、単なる会話の雰囲気だけでなく、確認の挟み方、使うモデル、ツール実行の進め方にも影響する。

## 5. 記憶方針

ChatGPTのように会話ログ上限で記憶が消えない設計を目指す。

PersonalAIでは以下の方針にする。

- 会話ログは原則保存
- 重要記憶は基本忘却しない
- 重要な記憶を忘却・削除・無効化する場合はユーザー許可を取る
- 低重要度情報は削除ではなく、まず圧縮・要約・Archive化する
- Project Stateを持ち、会話が切れても再開できるようにする
- 記憶には重要度・鮮度・信頼度・参照元を持たせる
- 古い情報と新しい情報の矛盾を管理する

記憶は以下のように階層化する。

- Raw Log
- Turn Summary
- Session Summary
- Project State
- Long-term Memory
- Knowledge
- Archive
- Deletion Candidate

Memory物理削除は慎重に扱う。
削除より先に、無効化、Archive化、圧縮、要約を検討する。

Ver2.9では、Reader結果のMemory保存方針を `docs/reader_memory_policy.md` に分けて整理した。
Reader結果は勝手に長期Memoryへ保存せず、Memory Candidate、Project Knowledge、User Preference、Archiveなどの段階を通して扱う。
機密情報、個人情報、長文本文は特に慎重に扱い、必要に応じて保存前にユーザー確認する。
Ver2.12では、Memory Candidate確認UI方針を `docs/memory_candidate_ui_policy.md` に分けて整理した。
保存前にユーザーが確認できる形を優先し、高リスク候補は自動保存しない。

## 6. ModelRouter / ToolRouter 方針

Qwen / OpenAI / Claude / Gemini などは、PersonalAIそのものではなく、PersonalAIが使う道具として扱う。

役割:

- PersonalAI = 司令塔
- Qwen = ローカルLLMツール
- OpenAI = 高性能LLMツール
- Claude / Gemini = 必要に応じて追加できるLLMツール
- Web Reader / PDF Reader / Image Reader / YouTube Reader / File Reader = 読み取りツール
- Git / PowerShell / Code Editor = 実行ツール

Qwenに難しい判断を無理に任せない。

ModelRouter / ToolRouterは以下を重視する。

- 精度最優先
- ルールベース + スコア + 高性能モデルへのエスカレーション
- 低リスク・低難易度はQwen
- 高難易度・高リスク・重要判断はOpenAIなど高性能モデル
- 危険操作はモデルに関係なくユーザー確認
- 失敗時は別モデル・別ツールへ切り替える

判断基準:

- タスク種類
- 難易度
- リスク
- 必要な情報源
- 必要な精度
- コスト設定
- プライバシー
- ユーザー設定

ModelRouter / ToolRouterは、安いモデルを使うためだけの仕組みではない。
ユーザーの目的を達成するため、精度、安全性、コスト、速度のバランスを取る仕組みである。

## 7. 自律調査・情報収集方針

PersonalAIは、ユーザーから話しかけられたときだけでなく、必要に応じて自律調査・情報収集できるようにする。

用途:

- 新しいAIモデルやAPIの更新確認
- PersonalAIに使えそうなツールやライブラリ調査
- 開発中プロジェクトに関係ある情報収集
- ユーザーの好みに合いそうな情報発見
- 価格・仕様・ルール変更の確認
- エラー解決に必要な情報検索
- セキュリティ上重要な更新確認

ただし、無制限にネットを徘徊する設計にはしない。

設定できるようにする項目:

- 調査対象
- 調査頻度
- 情報源の優先度
- 通知レベル
- 外部送信制限
- コスト上限

設定変更・課金・外部送信・購入・契約・アップデート反映は必ず確認する。

## 8. 自己アップデート方針

将来的にPersonalAIは、自身のツールやモデル更新を検出し、ユーザーに提案できるようにする。

想定フロー:

1. 新しいOpenAIモデルが利用可能になったことを検出する
2. 現在のモデルより有利か比較する
3. コスト・速度・精度・互換性を整理する
4. ユーザーに変更してよいか確認する
5. 許可後に設定変更する
6. テスト実行する
7. 問題があればロールバックする

禁止事項:

- PermissionManagerを勝手に緩めない
- 安全チェックを勝手に削除しない
- DBを勝手に初期化しない
- 料金が増える変更を勝手にしない
- 外部APIキーや個人情報を勝手に送信しない

自己アップデートは便利さのための機能であり、安全方針を回避するための機能ではない。

## 9. UI方針

完成形では、LINE / Discord風UIのような会話アプリ型UIを想定する。

必要な要素:

- メインチャット
- 通知
- 確認待ち
- タスク一覧
- 作業ログ
- Memory確認
- Permission設定
- ファイル / Knowledge

ユーザーがほとんどPersonalAI以外のアプリを触らなくても、開発・調査・作業できるレベルを目指す。

ただし、ゲーム開発の操作感確認など、人間の感覚が必要な部分は、ユーザーが確認し、AIへフィードバックする形も許容する。

## 10. 専門ツール候補

将来的には、専門作業用ツールも作れるようにする。

候補:

- KeyboardFirmwareHelper

目的:

- 分割キーボードのQMK / ZMK / VIA / Vialなどの設定・ドキュメントを読み取る
- 日本語でわかりやすく説明する
- キーマップ変更案を提案する
- ビルドエラー解説まで補助する

専門ツールは、汎用AIにすべてを任せるのではなく、特定分野の文脈、設定、失敗例、定番手順を扱いやすくするための補助レイヤーである。
